Windows x64 PFN(_MMPFN)

2026년 8월 31일/4분 읽기조회 –

#Windows Memory

목차
  • _MMPFN 구조체
  • PFN database
  • Windbg 실습

이전 포스트 Windows x64에서의 주소 변환 에서 Windows x64의 페이지 테이블 구조와 주소 변환 과정을 살펴보았습니다. 이번 글에서는 Windows x64에서 PFN(_MMPFN) 구조체에 대해 좀 더 자세히 알아보도록 하겠습니다.

_MMPFN 구조체

“페이지 프레임에 대한 위치를 나타내는 번호를 PFN(Page Frame Number) 이라고 합니다.” 라고 저번 포스트에서 언급했었습니다.

이런 페이지 프레임들을 관리하기 위해 Windows x64는 _MMPFN 구조체를 사용합니다. _MMPFN 구조체는 각 페이지 프레임에 대한 상태 정보를 담고 있으며, 메모리 관리에 중요한 역할을 합니다.


절대 PFN과 _MMPFN을 동일시하여 착각하면 안 됩니다. PFN은 페이지 프레임의 번호를 나타내는 값이고, _MMPFN은 해당 페이지 프레임에 대한 정보를 담고 있는 구조체입니다. (필자가 처음에 착각했었습니다. 여러분은 그러지 않길 바랍니다.)

0: kd> ?? sizeof(_MMPFN)
unsigned int64 0x30

0: kd> dt _MMPFN
nt!_MMPFN
   +0x000 ListEntry        : _LIST_ENTRY
   +0x000 TreeNode         : _RTL_BALANCED_NODE
   +0x000 u1               : _MIPFNFLINK
   +0x008 PteAddress       : Ptr64 _MMPTE
   +0x008 PteLong          : Uint8B
   +0x010 OriginalPte      : _MMPTE
   +0x018 u2               : _MIPFNBLINK
   +0x020 u3               : <unnamed-tag>
   +0x024 u5               : _MI_PFN_FLAGS5
   +0x028 u4               : _MI_PFN_FLAGS4

Windows x64에서 _MMPFN 구조체의 크기는 0x30(48) 바이트입니다. 8GB의 메모리를 사용하는 PC의 경우

메모리 8GB = 2^33 Byte 
페이지 크기 = 4KB = 2^12 Byte
페이지 프레임 수 = 2^33 / 2^12 = 2^21
전체 _MMPFN 구조체 크기 = 2^21 * 48 Byte = 100,663,296 Byte = 약 96MB

위와 같이 계산할 수 있습니다. 따라서 8GB의 메모리를 사용하는 PC에서는 _MMPFN 구조체를 관리하기 위해 약 96MB의 메모리가 고정적으로 필요한 겁니다.

PFN database


이미지 출처: Inside Windows Page Frame Number (PFN) - Part 1

_MMPFN 구조체들은 PFN database라고 불리는 구조체 배열 형태로 관리됩니다.
Active 외의 상태 (Standby, Modified, Free 등)의 페이지 프레임들에 해당하는 _MMPFN 구조체들은 이 PFN database에서 연결 리스트 형태로 관리합니다.
필요 시에 연결 리스트로부터 페이지 프레임을 가져와 Active 상태로 바꾸어 사용합니다.

0: kd> dq nt!MmPfnDatabase L1
fffff806`e21c6c78  ffffc800`00000000

_MMPFN 구조체 배열이 시작되는 주소 즉, PFN database 시작 주소는 nt!MmPfnDatabase 심볼을 통해 확인할 수 있습니다. 위의 예시에서는 0xffffc80000000000 주소에서 시작하는 것을 확인할 수 있습니다.

아까 8GB의 메모리를 사용하는 PC에서 전체 _MMPFN 구조체 크기가 약 96MB라고 했습니다.
따라서 대략적으로 0xffffc80000000000 ~ 0xffffc80006000000 범위에 _MMPFN 구조체가 존재하는 것도 예상할 수 있는 거죠.

PFN database 구조체 배열의 인덱스 번호는 PFN 번호에 해당합니다.
예시로 0xffffc80000000000 주소는 구조체 배열 0번째 인덱스이며, 해당하는 _MMPFN 구조체는 PFN 0번의 상태를 나타냅니다.
마찬가지로 0xffffc80000000030 주소는 구조체 배열 1번째 인덱스이며, 해당하는 _MMPFN 구조체는 PFN 1번의 상태를 나타냅니다.

_MMPFN 구조체 주소 = nt!MmPfnDatabase + (n * sizeof(_MMPFN))

따라서 PFN n번에 해당하는 _MMPFN 구조체의 주소는 위와 같이 계산할 수 있습니다.

Windbg 실습

Windbg를 이용한 커널디버깅을 통해 좀 더 자세히 알아보도록 하겠습니다.

PROCESS ffff8d0b1126d080
    SessionId: none  Cid: 0d6c    Peb: 9363a83000  ParentCid: 09dc
    DirBase: bcb49000  ObjectTable: ffff9d0d7ce3b880  HandleCount: 1254.
    Image: Notepad.exe

0: kd> !pte ffff8d0b1126d080
                                           VA ffff8d0b1126d080
PXE at FFFFFDFEFF7FB8D0    PPE at FFFFFDFEFF71A160    PDE at FFFFFDFEE342C448    PTE at FFFFFDC685889368
contains 0A00000101C13863  contains 0A00000101C16863  contains 0A000001FE561863  contains 8A000001AB724963
pfn 101c13    ---DA--KWEV  pfn 101c16    ---DA--KWEV  pfn 1fe561    ---DA--KWEV  pfn 1ab724    -G-DA--KW-V

notepad.exe 프로세스의 _KPROCESS 구조체의 pfn을 확인하는 과정입니다.
이전 포스트에서는 학습을 위해 직접 가상 주소를 물리 주소로 변환하는 과정을 거쳤지만, 이 과정을 Windbg에서는 !pte 명령어를 통해 제공합니다.

0: kd> dq ffff8d0b1126d080 L6
ffff8d0b`1126d080  00000000`00000003 ffff8d0b`113cb590
ffff8d0b`1126d090  ffff8d0b`113cb590 ffff8d0b`1126d098
ffff8d0b`1126d0a0  ffff8d0b`1126d098 00000000`bcb49000

0: kd> !dq 0x1ab724080 L6
#1ab724080 00000000`00000003 ffff8d0b`113cb590
#1ab724090 ffff8d0b`113cb590 ffff8d0b`1126d098
#1ab7240a0 ffff8d0b`1126d098 00000000`bcb49000

위는 _KPROCESS의 가상 주소와 그에 해당하는 물리 주소의 덤프 결과를 비교한 것입니다.
_KPROCESS가 존재하는 가상 주소 0xffff8d0b1126d080의 PTE는 pfn 1ab724의 값을 가집니다.
즉, 물리 주소 0x1ab724000에 offset 0x80에 해당하는 바이트를 더한 물리 주소값 0x1ab724080에서 _KPROCESS 구조체의 값을 확인할 수 있습니다.

0: kd> !pfn 0x1ab724
    PFN 001AB724 at address FFFFC800050256C0
    flink       00000000  blink / share count 00000001  pteaddress FFFFFDC685889368
    reference count 0001    used entry count  0000      Cached    color 0   Priority 0
    restore pte 00000080  containing page 1FE561  Active

pfn에 대한 정보를 확인할 수 있는 명령어를 windbg에서는 !pfn 명령어로 제공합니다.
명령어가 출력하는 내용 중 PFN 001AB724 at address FFFFC800050256C0 부분이 조금 헷갈리게 표현되어 있는데, PFN에 해당하는 _MMPFN 구조체의 주소가 FFFFC800050256C0라는 의미입니다.
또한 !pfn 명령어를 통해서 해당 페이지 프레임이 Active 상태인지, Standby 상태인지, Modified 상태인지 등 다양한 정보도 확인할 수 있습니다.

_MMPFN 구조체 주소 = nt!MmPfnDatabase + (n * sizeof(_MMPFN))

0xffffc80000000000 + (0x1ab724 * 0x30) = 0xffffc800050256c0

당연히 pfn에 해당하는 _MMPFN 구조체의 주소를 직접 계산해볼 수 있습니다.
위의 계산 결과와 windbg에서 확인한 주소가 정확히 일치하는 것을 확인할 수 있습니다.
