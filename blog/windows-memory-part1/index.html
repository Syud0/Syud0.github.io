Windows x64 페이지 테이블 포맷

x64에서는 다음과 같은 4-Level 페이지 테이블을 이용하여 가상 주소를 물리 주소로 변환합니다.

정규 주소

8바이트의 가상 주소를 사용할텐데 왜 48비트만 물리 주소를 찾는데 사용하지?

그림을 보면 이런 의문이 들 수 있습니다.

Windows Server OS가 아닌 Windows OS의 x64의 경우엔 가상 주소 공간을 64비트로 정의만 해둔채로 실제 가상 주소 공간의 사용은 48비트만 사용하기 때문입니다.

가상 주소 중에서 실제로 사용가능한 주소를 정규 주소라고 부르며, 규칙은 아래와 같습니다.

  • Bit 47 : 0이면 상위 16비트도 전부 0, Bit 47 : 1이면 전부 1이어야 한다.
  • Bit 47의 값의 여부에 따라 유저모드(Bit47 : 0)와 커널모드(Bit47 : 1) 영역이 나눠진다.
  • Bit 47 : 1이라면 Bit46 : 1이여야 하며, Bit 47: 0이라면 Bit 46: 0이여야 한다.

따라서 정규 주소의 범위는 아래의 표와 같이 나눠지게 됩니다.

영역범위
Lower half (User)0x0000_0000_0000_0000 ~ 0x0000_7FFF_FFFF_FFFF
non-canonical hole그 사이 전부
Upper half (Kernel)0xFFFF_8000_0000_0000 ~ 0xFFFF_FFFF_FFFF_FFFF

CR3? KPROCESS? PFN?

그림에 등장하는 용어들에 대해서 좀 더 자세히 알아보도록 하겠습니다.


각 프로세스마다 자신만의 고유 페이지 테이블을 갖고 있습니다. 그렇기 때문에 Windows는 프로세스 생성 시 KPROCESS에 해당 프로세스의 페이지 테이블의 물리 주소를 저장해둡니다.
Context Switching 때 KPROCESS에 저장된 페이지 테이블의 주소를 CR3 레지스터에 로드합니다.
이후 MMU는 가상 주소를 물리 주소로 변환할 때 CR3를 참조하여 물리 주소로 변환하는 과정을 거칩니다.


Windows x64에서는 가상 주소를 페이지(4KB) 단위로 나누고 관리합니다. 마찬가지로 물리 메모리 또한 페이지와 같은 크기로 공간을 나누어 관리하며, 이 공간을 페이지 프레임이라고 합니다.
그리고 이 페이지 프레임에 대한 위치를 나타내는 번호를 PFN(Page Frame Number) 이라고 합니다.

예시를 하나 들어보겠습니다. PFN: 0x99인 경우 물리 주소는 어떻게 될까요??
물리 주소는 0x99000이 될 것 입니다. 앞서 언급한 “프레임 또한 4KB의 크기(0x1000 Byte)로 나눠져 관리된다.” 이유 때문입니다.
즉, PA(물리 주소) = PFN * 0x1000 공식을 세울 수 있습니다.


다음으로 페이지 테이블에 저장되는 엔트리(항목)의 명명법을 살펴보겠습니다.
페이지 테이블(PML4, PDP, PD, PT)은 저마다의 고유한 테이블을 갖고 있습니다. PML4 테이블의 엔트리는 PML4E, PDP 테이블의 엔트리는 PDPE 이런 방법으로 명명이 됩니다.

각 레벨의 페이지 테이블 마다의 크기는 어떻게 되는지 계산해보겠습니다. PML4, PDP, PD, PT 각 테이블은 테이블의 엔트리(항목)를 찾는데 인덱스로 9비트를 사용합니다.
즉, 각 테이블이 가질 수 있는 엔트리의 갯수는 2^9 = 512개 입니다. 테이블은 저마다의 고유한 엔트리를 가지고 있습니다만, 전부 8바이트의 동일한 크기의 엔트리입니다.
따라서 테이블(PML4, PDP, PD, PT 상관없이) 하나의 크기는 512 * 8 Byte = 4096 Byte 입니다.

가상 메모리에서 각 테이블의 인덱스에 해당하는 값을 추출하는 자동화 스크립트를 실행해보겠습니다.

va-decode.py49줄
"""
usage:
    python va-decode.py 0x0000018f35df1040
    python va-decode.py 677101f000 ffffd687be3c9080
"""

import sys

FIELDS = [
    ("Sign Extension", 63, 48),
    ("PML4 Index", 47, 39),
    ("PDPT Index", 38, 30),
    ("PDT Index", 29, 21),
    ("PT Index", 20, 12),
    ("Offset In Page", 11, 0),
]


def extract(addr, hi, lo):
    width = hi - lo + 1
    return (addr >> lo) & ((1 << width) - 1)


def decode(addr):
    print(f"Virtual Address: 0x{addr:016x}\n")
    print(f"{'Bits':<7}  {'Field':<16}  {'Binary':<16}  {'Hex':>6}  {'Dec':>6}")
    print("-" * 60)

    for name, hi, lo in FIELDS:
        width = hi - lo + 1
        value = extract(addr, hi, lo)
        bits = f"{value:0{width}b}"
        print(f"{hi:>2}:{lo:<4}  {name:<16}  {bits:<16}  0x{value:04x}  {value:>6}")


def main(argv):
    if not argv:
        print(__doc__)
        return 1

    for i, arg in enumerate(argv):
        if i:
            print()
        decode(int(arg, 16))
    return 0


if __name__ == "__main__":
    sys.exit(main(sys.argv[1:]))

테이블의 엔트리 크기는 8Byte 이므로, 엔트리 물리 주소 = PFN * 1000 + 8 * Index 식이 세워질 수 있습니다.
CR3에는 PFN이 아닌 물리 주소가 저장되기 때문에, PML4E의 위치 계산 시에는 PFN * 1000을 생략하고 그 자리에 CR3 레지스터의 값을 사용하면 됩니다.
따라서 PML4E = 0x12e72a000 + 0x8 * 0x0004 = 0x12e72a020 이며, 해당 위치의 물리 주소에 접근하여 8바이트의 값을 읽으면 엔트리의 값을 알 수 있습니다.

물리 주소 0x12e72a020에 저장된 PML4E의 값은 0x0a0000008425a867 입니다.
각 계층 페이지 테이블의 엔트리마다 조금씩 다른 구조를 갖고 있습니다만, 공통적으로 PFN을 추출하는 방법은 동일합니다.
PFN은 엔트리의 8바이트 중 Bit 51 ~ Bit 12에 해당하는 값입니다.
엔트리 값에서 PFN을 추출하는 자동화 스크립트를 실행해보겠습니다.

pfn-decode.py52줄
"""
usage:
    python pfn-decode.py 0x0a0000008425a867
    python pfn-decode.py 0x0a0000008425a867 0x0a00000012c0d867
"""

import sys

FIELDS = [
    ("Reserved", 63, 52),
    ("PFN", 51, 12),
    ("Flags", 11, 0),
]

PAGE_SIZE = 0x1000


def extract(entry, hi, lo):
    width = hi - lo + 1
    return (entry >> lo) & ((1 << width) - 1)


def decode(entry):
    print(f"Page Table Entry: 0x{entry:016x}\n")

    print(f"\n{'Bits':<7}  {'Field':<10}  {'Hex':<12}  {'Dec':>8}")
    print("-" * 43)

    for name, hi, lo in FIELDS:
        width = hi - lo + 1
        value = extract(entry, hi, lo)
        hexed = f"0x{value:0{(width + 3) // 4}x}"
        print(f"{hi:>2}:{lo:<4}  {name:<10}  {hexed:<12}  {value:>8}")

    pfn = extract(entry, 51, 12)
    print(f"\nPFN * 0x{PAGE_SIZE:x} = 0x{pfn * PAGE_SIZE:x}")


def main(argv):
    if not argv:
        print(__doc__)
        return 1

    for i, arg in enumerate(argv):
        if i:
            print()
        decode(int(arg, 16))
    return 0


if __name__ == "__main__":
    sys.exit(main(sys.argv[1:]))

PFN * 0x1000 = 0x8425a000

따라서 PML4E에서 PFN을 추출하면 0x8425a 입니다.

총 40개의 비트를 사용하여 PFN을 나타내는 것은, 2^40 * 2^12 Byte(4KB) = 2^52 Byte = 4PB의 물리 메모리까지 최대로 접근이 가능할 수 있다는 것을 의미합니다.
하지만 실질적으로 Windows x64는 128GB(home), 2TB(Pro), 24TB(Server Standard, Server Datacenter)까지의 물리 메모리만 지원합니다.

다시 본문으로 돌아와 마저 이어가보도록 하겠습니다. PML4E에서 추출한 PFN : 0x8425a은 PDPT의 물리 주소를 나타냅니다. 따라서 PDPTE의 위치는 0x8425a * 0x1000 + 0x8 * 0x017b = 0x8425abd8 입니다.

PDPTE에서 앞전 과정과 동일한 방법으로 추출한 결과입니다. PDPTE가 가르키는 PFN : 0xaaa5b은 PDT의 물리 주소를 나타낼거라 예상할 수 있습니다.
동일한 방법을 반복하여 PDTE, PTE를 구할 수 있으며, 최종적으로 PTE에서 추출한 PFN과 가상 주소의 Offset In Page를 합쳐서 물리 주소를 구할 수 있습니다.
